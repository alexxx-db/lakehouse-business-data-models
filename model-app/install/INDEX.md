# install/

First-time (and idempotent re-run) workspace install. See `INSTALL.md` for the operator guide.

Self-contained: files here only reference `install/`, `src/app/` and root config (`databricks.yml`).

- `install.sh` — End-to-end installer: preflight, `bundle deploy`, Lakebase provisioning, catalog grants, the optional model-service check (`--enable-taxonomy-builder [--taxonomy-model-service <catalog.schema.service>]`), the optional assessment (`--enable-assessment [--assess-reader-sp <application_id>]`, with a warn-only reader check), app start + deploy, warn-only verification.
- `in_flight_guard.sh` — Refuses a (re-)deploy while the existing App reports in-flight runs on `/api/health` (exit 2; `FORCE=1` overrides); no-op on a fresh install. Also used by the other deploy scripts.
- `clear_stale_bundle_state.sh` — Clears the local `.databricks/bundle/<target>/terraform` state when it pins a different workspace than the profile resolves to (avoids the `workspace_id mismatch` deploy error); advisory, always exit 0. Also used by the other deploy scripts.
- `build_and_render.sh` — Bundle artifacts hook (`--bundle-hook`, passed on to the render), also run by `install.sh` and the other deploy scripts before `bundle deploy`: `apx build` (wrapped in `frontend_lock_guard.py`), then renders `src/app/.build/app.yml` from the exported `VIBE_MODELING_*` values and, from the same assessment flag, `install/.generated/app_scopes.yml` (the `databricks.yml` include for the App's `user_api_scopes`; gitignored); echoes the effective taxonomy and assessment flags.
- `frontend_lock_guard.py` — Runs a build command in `src/app`; when it changed the meaning of `package.json` (dependency specs, overrides) or `bun.lock` (workspace specs, overrides, per-package `name@version` + integrity; header, formatting and tarball URLs ignored), restores both files and exits 1 with a diff and fix steps for installers and maintainers. Catches apx's per-build `bun add --dev` moving the frontend devDependencies off the `overrides` pins in `package.json`.
- `render_app_yaml.py` — Line-oriented rewrite of the known `app.yml` env values (`ENV_TARGETS`), incl. `VIBE_MODELING_TAXONOMY_BUILDER_ENABLED` / `VIBE_MODELING_TAXONOMY_MODEL_SERVICE` and `VIBE_MODELING_ASSESSMENT_ENABLED` / `VIBE_MODELING_ASSESS_READER_SP`; every value is written as an escaped YAML double-quoted scalar; `render_bundle_scopes` + `--bundle-scopes-out` write the App's `user_api_scopes` fragment: a per-target override (`BUNDLE_TARGETS`, kept equal to `databricks.yml`'s targets by a test) with `workspace.workspace` when the assessment is on, deleted when it is off (never an empty list; a redeploy without the flag drops the scope); with `--bundle-hook` (the `databricks.yml` build hook) a changed fragment, incl. absent vs present, exits 3 with "re-run the deploy", since the bundle already loaded the old one.
- `provision_lakebase.py` — Lakebase project, endpoint, database and role grants for the app SP.
- `grant_catalog.py` — Best-effort UC catalog/schema grants + `_metamodel` schema/volume creation for the app SP (loads `backend/services/metamodel_setup.py` by file path); the `_metamodel` grant includes `CREATE_VOLUME` and `MANAGE` on every install (the assessment runs volume and the reader's USE SCHEMA).
- `check_model_service.py` — Read-only check that the app SP can use a UC model service (exists; EXECUTE / USE CATALOG / USE SCHEMA via effective permissions, ALL_PRIVILEGES or ownership); stops with `databricks grants update` commands on a missing privilege, warns when it can't verify; never grants. `--validate-only` checks just the three-part name (rule loaded by file path from `backend/taxonomy/service_name.py`). `--principal <reader>` (default: `--app-sp`) checks the assessment reader instead, WARN-ONLY (exit 0): also warns when the reader does not exist, and prints a reminder (no check) that the app SP needs the Service Principal User role on it.
