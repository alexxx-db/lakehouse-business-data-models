# Frontend index

React + Vite app under `src/app/src/vibe_modeling/ui/`. TanStack Router (file-based), shadcn/ui, Orval-generated API client, Tailwind v4. One line per file/dir; keep current-state only when adding/moving/removing.

## Routes (TanStack file-based)

- `routes/__root.tsx` — Top-level layout (ThemeProvider, Toaster, Outlet).
- `routes/route.tsx` — Authenticated `_sidebar` layout shell + navigation.
- `routes/_sidebar/index.tsx` — Home page: workflow orientation strip, "Jump back in" (businesses, industries and visited model versions by per-user visit recency), pruning stale visit rows on load, "Start something new" entry points.
- `routes/_sidebar/profile.tsx` — Profile view: identity, display name and emails from `/current-user`.
- `routes/_sidebar/settings.tsx` - Settings: six URL-backed tabs (`?tab=`): **agent** (notebook path, runtime concurrency/statistics), **platform** (metamodel-catalog card wired to get/setMetamodelCatalog with inline `^[a-z][a-z0-9_]+$` validation + SQL warehouse + the Domain Taxonomy Builder card `components/settings/taxonomy-builder-card.tsx`, rendered only when installed), **sources** (`GithubConfigSection` repo owner/name + auth mode + UC connection name, plus the anonymous-mode rate-limit banner driven by `getSourceCapabilities.auth_mode`), **assessment** (`AssessSettings` inside `AssessBoundary`, admin-gated), **sectors** (CRUD), **preferences** (per-user diagram column-mode defaults + reset-to-defaults). `validateSearch` redirects legacy deep-links `diagram`->`preferences`, `warehouse`->`platform`, `github`->`sources`.
- (The source explorer is no longer a standalone route. It is hosted in `components/source-explorer/source-explorer-dialog.tsx`, launched from the Industries page "Download from source" button.)
- `routes/_sidebar/businesses.{index, new, tsx}.tsx` — Business list + creation.
- `routes/_sidebar/businesses.$businessId.{tsx, index, edit, explorer, runs}.tsx` — Per-business shell, redirect, edit (incl. the proposed Business domains `TagInput` + Organization divisions select - a stored non-preset shows as "Current: <value>" - sent patch-style only when changed), model explorer (with friendly 404), runs list. The explorer header carries a "Kickstart a business" action (gated on `kind === "industry"`, opens `KickstartDialog`) and a "Kickstarted from <industry> v<n>" provenance line for kickstarted businesses (`source_industry_id`).
- `routes/_sidebar/businesses.$businessId.runs.{new, $runId}.tsx` — New Run form (dispatches exactly the server-persisted `selected_for_run` set; shows a read-only scrollable compiled-instructions preview of that set + the per-run instructions editor + an "Edit inputs →" back-link to Compose; Business Domains + Organization Divisions pre-fill from the business's stored `business_domains`/`org_divisions` only for New Base Model on a business without versions), run-detail page with cancel dialog.
- `routes/_sidebar/businesses.$businessId.assessments.tsx` — layout `<Outlet/>` for the assessment routes inside `AssessGate` (the not-installed page when the skill isn't installed).
- `routes/_sidebar/businesses.$businessId.assessments.index.tsx` — Assessments list page: batches table (created, `v{version} {scope}`, domain count, roll-up `StatusBadge`, creator, Relaunch for batches with a failed run) linking to the batch page, plus a "New assessment" link to the wizard; while not ready the results stay readable, New assessment and Relaunch are hidden and `AssessNotReady` shows.
- `routes/_sidebar/businesses.$businessId.assessments.new.tsx` — New assessment page; validates `?versionId=&domainId=` search params and renders `AssessmentWizard` in an `AssessBoundary` behind `AssessGate requireReady` (the not-set-up notice until ready).
- `routes/_sidebar/businesses.$businessId.assessments.$batchId.tsx` — assessment batch page; renders `BatchStatus` in an `AssessBoundary`.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.{tsx, index, $domainName.*}.tsx` — Model version pages: overview, per-domain, per-product. Each of the three has a friendly not-found card that resets when the route params change.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.inputs.{tsx, index, $inputId}.tsx` — Vibe Inputs compose surface (ComposeSurface) + card-details page (metadata/instruction over the scoped ModelView viz tabs).

## Components (by feature)

- `components/ui/free-text-combobox.tsx` — `FreeTextCombobox`: Popover + Command picker over a list that also accepts a typed value ("Use '<input>'"), client-side filter, plain-input fallback when the list failed; used by the deployment-catalog picker and the taxonomy model-service picker.

- `components/overview/` — Model-version overview tab band (Model Evolution Metrics). `metrics.ts` — pure `deriveOverviewMetrics(model, {feedbackCount, runsCount, evolution, nextVibe})` → the four areas (Change / Quality / Review / Size+effort) plus `confidenceDeltaTone` (±5-point colour rule). Evolution (T16) backs confidence + delta + version sparkline, open-issue severity split, Δ-open-issues and tokens/hours effort; next-vibe (T13) backs the Quality Score. The "uncomputable → `??`" rules are flag-driven: ECM (`has_confidence` false) has no confidence/issues/sparkline; a base version (`has_predecessor` false) has no delta/sparkline/Δ-issues; `% touched` stays `??` (no per-product diff on the wire); effort degrades when evolution recorded none. `metrics-band.tsx` — `MetricsBand`, Direction A insight-strip render (4-cell hairline-divided scoreboard: hero + supporting per area, inline SVG `Sparkline`, `DeltaChip` colour rules, severity split, `??` tooltip placeholders, action links into Feedback). `command-strip.tsx` — `CommandStrip`, the compact bordered action row replacing the old Actions + Runs cards (Install/Uninstall/Generate samples/Re-sync + Prepare new Vibe launcher (opens the compose surface), with run-status summary + Installed badge). `publish-version-dialog.tsx` — `PublishVersionDialog`, the "Publish to GitHub" command-strip action: opens a PR for the version's artifacts via `usePublishModelVersion`; pre-checks `useGetGithubConfig` (non-suspense) and disables the trigger with a `/settings?tab=github` tooltip link when `connection_name` is empty; degrades a 422 (`github_connection_missing` / `github_pat_not_implemented`) into the same Settings link inline; renders the resulting PR number/url/branch/files on success.

- `lib/client-telemetry.ts` — `reportClientGatewayError()`: records a browser-observed transient gateway error in BOTH the console and the app logs (fire-and-forget beacon to `POST /api/client-telemetry/gateway-error`), so an E-04-style 502 stays diagnosable in `databricks apps logs` even when a client retry recovers it.
