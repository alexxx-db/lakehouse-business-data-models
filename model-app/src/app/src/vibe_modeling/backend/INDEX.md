# Backend index

FastAPI app under `src/app/src/vibe_modeling/backend/`. One line per file/dir; keep current-state only when adding/moving/removing.

## Taxonomy builder

- `taxonomy/models.py` — Pydantic shapes for `/api/taxonomy/*` (intake, tree, sections with per-claim provenance, draft parts incl. the `busy` part/draft status, compile in/out, example) and `/config/taxonomy` (`TaxonomyConfigIn/Out`, `TaxonomyCheckOut`, `TaxonomyModelServicesOut`, `ProbeStatus`); section keys/headings. The intake name pattern and the tree's `coverage` type (`OrgDivisions`) come from `models.py`, the single definitions.
- `taxonomy/naming.py` — `snake()` ASCII-folding snake_case (byte-parity with `ui/lib/taxonomy/tree.ts` via `tests/fixtures/taxonomy_snake_fixture.json`) + `SCHEMA_NAME_RE`.
- `taxonomy/compile.py` — pure tree → clamp (strict/guided), business vibes (sections in fixed order + clamp; division names appended to the company section), `business_domains` seed, CSV, and issues (error: invalid/duplicate schema name, unknown shared-master home; warning: empty nodes, entity in 2+ domains); blank categories are skipped defensively.
- `taxonomy/rules.py` — model-agent naming rules from the vendored `vendored/agent/vibe-data-modelling-rules.csv`; `APPLIED_RULES` (id -> error/warning/split, DOM-RUL-002/004/006/007/016/020/021/024/027/030/032/037/040). `rule_issues(tree)` -> errors (schema format/length, forbidden tier-1, duplicate schema, <3 domains; block Create) + warnings (plural, tier-2, sub-domain two-word/shared-word/cross-domain/placeholder/single), each with `rule_id` + domain indices. The only copy of the rules: the UI shows the compile response's issues (golden output: `tests/fixtures/taxonomy_rules_fixture.json`). `naming.schema_for` = override else snake(name) without underscores (`taxonomy_schema_fixture.json`); `SCHEMA_NAME_RE` is one lowercase word.
- `taxonomy/llm.py` — TaxonomyLLM(ws, model_service): JSON-only completion through the Unity AI Gateway (`ws.api_client.do(POST /ai-gateway/mlflow/v1/chat/completions, {model, messages, max_tokens})`), fence/prose-tolerant extract_json, one corrective retry. Error classifier walks the exception + `__cause__`/`__context__`: 429/503 -> `TaxonomyLLMBusy`, 401/403 -> `TaxonomyLLMDenied` (names the SP id), 404 -> `TaxonomyLLMNotFound`, else `TaxonomyLLMError`; `error_text` unwraps OpenAI-style bodies and drops the SDK config debug suffix. `probe()` -> `ProbeResult(ok|denied|not_found|busy|error, message)` (one `max_tokens=5` call; any 2xx with `choices` is ok; on a gateway 404 a UC GET of the service tells "not found" from "exists but not usable yet" - the gateway 404s for a minute or two after a grant). `make_taxonomy_llm(model_service)` on the shared lazily-built SP `llm_workspace_client()` (90 s HTTP timeout, 1 s retry budget) is the one LLM client factory (routes, Settings, boot probe).
- `taxonomy/access.py` — `ModelServiceAccess` (`MODEL_SERVICE_ACCESS`): in-process probe cache (services whose last test call was ok, expiring after `PASSED_TTL` = 15 min so the pre-draft probe runs again) + `last_check` per service; draft calls that come back denied/not_found are recorded too (`now()` + `record(..., not_before=)` so a newer Test wins); `probe()` runs `TaxonomyLLM.probe` on the taxonomy executor under one slot with a 20 s wait; no free slot or the wait expiring is `busy` (recorded, never cached); denied/not_found/error (`REFUSED_CHECKS`) drop the cache entry. Self-healing: `maybe_recheck` (from `GET /config/taxonomy`) starts one deduplicated fire-and-forget background probe when the last check is refused and older than `REFUSED_RECHECK_AFTER` (5 min); `start_background_probe` also runs at boot; a background result never overwrites a check stored after the probe started (`record(..., not_before=)`), and the in-flight marker clears on any submit failure or probe exception.
- `taxonomy/slots.py` — `LLMSlots`: lock-guarded app-wide hard cap on live LLM calls (1-16, default 6; `try_acquire` never waits; `set_capacity` never preempts). `submit`/`run` take a slot and release it in the executor future's done-callback (idempotent, registered before `asyncio.wrap_future`), so a slot frees when the thread ends, not when the awaiting task is cancelled. `TAXONOMY_EXECUTOR`: dedicated 16-thread pool (`taxonomy-llm`); `TAXONOMY_SLOTS`: the one app-wide counter; its capacity is set only by `DraftStore`.
- `taxonomy/service_name.py` — stdlib-only UC model-service name rule (`catalog.schema.service`, mirrors the gateway's check) + `model-services/` prefix strip; also loaded by file path from `install/check_model_service.py`.
- `taxonomy/prompts.py` — (system, user) builders for the tree call (rejected/placeholder/avoid name lists built from `rules.FORBIDDEN_DOMAINS`, `rules._PLACEHOLDERS`, `PROMPT_AVOID`), each of the six section calls (per-claim provenance rules; systems-of-record forbids invented vendor names), and the ≤limit-char description condense; Ridgeline as the few-shot example.
- `taxonomy/drafts.py` — DraftStore: in-memory per-owner drafts (TTL 1h), background asyncio tasks (tree first, then up to six sections); every LLM call takes a `TAXONOMY_SLOTS` slot on `TAXONOMY_EXECUTOR`, and the store is the one owner of the slot capacity (applies `max_concurrency` on every create and retry). Per-part 210 s ceiling from submit (`timed_out`). A part (tree, section or description) takes a slot before it starts; with none free it stays `pending` while its draft has calls in flight (running siblings or calls a cancel/retry abandoned) and is `busy` only when nothing of the draft is in flight; a rate-limited call is `busy` too, and a busy tree leaves the sections busy "waiting for the domains". Draft-time denied/not_found is recorded in `MODEL_SERVICE_ACCESS` (with `not_before` = the call's start) and fails the part plus the draft's not-started parts with the same message (a refusal from a call started before the current attempt is ignored); a failing prompt build fails only its part. `wait()` (tests) waits only on unfinished tasks; `_active` is derived from live tasks. One active draft per user per kind (create vs condense; synchronous bookkeeping on cancel and purge); per-part retry of failed/cancelled/timed-out/busy parts incl. the condense `description`; `busy=True` reports the part busy without a call (busy pre-draft probe).
- `taxonomy/example.py` + `taxonomy/examples/` — the Ridgeline Energy example (CSV + business vibes + description + meta) used for few-shot prompts, the "See a finished example" toggle, Skip drafting, and the golden compile test.

## Sync + read paths

- `model_sync.py` — model.json → Lakebase (Domain/Product/Attribute/FK), Delta `_metamodel.*` writes + reads; threads `run_id` → `_link_previous_version` lineage pass (synchronous final drain on Session-Ended, then `model_lineage`). Structured next-vibes ingestion (ADR D-044/D-045) is the SINGLE producer of `VibeInput(agent_next_vibe)` rows: `_capture_run_metadata` (threaded `run_id`) loads the next-vibes artifact `(payload, path)`, `_parse_next_vibes_findings` classifies `next_vibes.txt` into per-finding category/severity/target/Quality Score (`_next_vibes_payload_from_txt` builds the structured payload directly, no blob), `materialize_next_vibe_inputs` writes anchored rows at sync time (idempotent uuid5, shared `anchor_resolve` resolver), and `register_next_vibes_artifact` registers the raw txt as a `RunArtifact`. The legacy `next_vibes_json` blob is retired (dropped in `v_0_6_4`).
- `model_export.py` — inverse of `model_sync.sync_from_model_json`: reads a version's Lakebase Domain/Product/Attribute rows via a Session and reconstructs the agent-envelope `model.json` (`export_model_json`); `bundle_layout`/`BundleLayout` is the single code-level on-disk layout descriptor (`<industry>/<scope>_vN/`); `iter_bundle_files` is the single source of truth for a bundle's contents (model.json + companion artifacts, with collision dedupe), consumed by both `build_bundle_zip_bytes` (the downloadable zip) and `services/github_publish.py` (the published tree) so the two can't diverge. Surfaced by the read-only `exportModelJson` / `exportModelBundle` routes.
- `model_lineage.py` — rename/merge/delete lineage resolver: reads `RunProgressEvent` signals, sets `previous_element_id` pointers (exact/rename tiers), writes `RunElementLineage` merge/delete/rename rows, upserts subdomains (uuid5 natural key converging with Task 3).
- `explorer.py` — Lakebase-first model explorer with Volume JSON fallback (`_read_volume_json` shared by `_load_model` + `_load_model_json_envelope`); in-memory cache invalidation; product-canonical review reads (`listProductReviews` effective per-product states, `getReviewProgress` rollup) + `ModelSummaryOut.review_pct` via `review.compute_progress`; next_vibes metrics reads (`getNextVibeMetrics` model scope, `getDomainNextVibeMetrics` domain scope) via `next_vibe_metrics`; evolution metrics read (`getEvolutionMetrics`, model scope) via `evolution_metrics` off the raw Volume `model.json` envelope.
- `review.py` — product-canonical review spine (ADR D-044): the computed default-state rule (`no_review_needed` iff unchanged + no open issues, else `not_reviewed`; base version has no predecessor → nothing auto-`no_review_needed`), effective-state resolution over the sparse `product_reviews` rows + the change diff + the (degrading) open-issue gate (agent-origin anchored VibeInputs), and the product-level progress measure + per-domain rollup.
- `next_vibe_metrics.py` — next_vibes "expected work" metrics (T13, ADR D-044): aggregates the open (active, non-consumed) `agent_next_vibe` VibeInput backlog anchored to a version into the Model Quality Score (mean of in-scope `confidence_score`), per-`NextVibeCategory` open counts, and `total_open`. Model scope = any anchor; domain scope resolves anchors via direct `domain_id` or the product → domain map. Reuses `review`'s origin/status string literals so the two open-input readers can't drift; degrades to zeros/null + `has_data=False` pre-ingestion.

## Sources (external catalog seam)

- `sources/base.py` — `SourceConnector` ABC + value types (Wave 1 Track C): browse (`list_sectors`/`list_industries`/`list_models`) + fetch (`fetch_model_json`/`fetch_artifacts`) + `capabilities()` self-description. Capabilities carry the three axes — `TargetKind` (element kinds the source provides), `DiscoveryMode`, `MaterializationTiming` — plus `provides_sectors`. Error types: `SourceError` base, `SourceNotFoundError` (404), `SourceRateLimitError` (429), `SourcePermissionError` (401/403 access denial → HTTP 403). Source-agnostic so a future lakehouse/Volume source slots in behind the same ABC (no source registry).
- `sources/github.py` - `GithubSourceConnector` + `build_github_connector` (+ `GithubAppTransport`/`GithubAppCredentials`; `UcConnectionTransport` retained for the future publish path). Read-only repo browse via the GitHub contents API + `raw.githubusercontent`. Read-transport precedence (per install, via `build_source_connector` → `resolve_source_transport` off the `AgentConfig.source_*` columns): explicit `http=` override > configured mode (`github_app` / `token`) > `AppConfig` env GitHub App fallback > anonymous `requests`. Secret material (App PEM, PAT) is referenced by scope/key and read from a Databricks secret scope by the app SP via `_read_secret` (short-TTL cache, leak-free degrade to anonymous+error, never 500). `BearerTokenTransport` sends `Authorization: Bearer <pat>` and, like `GithubAppTransport`, routes file reads through the Contents-API raw-media rewrite at 5,000 req/hr; `capabilities().auth_mode` is `token`/`github_app`/`anonymous` with an optional `auth_error`. With App creds, `GithubAppTransport` signs an RS256 JWT (pyjwt), mints a 1h installation token (module-level cached, refresh at expires_at-300s or on 401), calls `api.github.com` with `Authorization: Bearer <token>` at 5,000 req/hr (immune to the industry repo's SAML SSO), and routes file reads through the Contents API with `application/vnd.github.raw+json` via the shared `_translate_github_url` rewrite; `capabilities().auth_mode` is `github_app`. No App creds → anonymous (60 req/hr), `auth_mode=anonymous`. The per-user `oauth_u2m` UC connection is NO LONGER selected for reads (EMU/SAML-blocked on the test workspace). Flat repo (industries at root, no sector level) → one synthetic sector; default repo from `agent_config` when set. `fetch_readme` (scope readme, version-readme fallback, `None` on both-missing) + `fetch_releasenotes` (best-effort, `None` on any failure) + module-level `parse_model_statistics` (parses a release-notes "MODEL STATISTICS" block by label, never by line order; all-null on an absent/unparseable block) back the preview's README + domain-statistics fields.
